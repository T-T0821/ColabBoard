# エンドツーエンド暗号化ボード

サーバーの管理者にも中身が見えないボード。ボードの中身(付箋・図形・画像・線など、yrs の更新すべて)を
ブラウザの中で暗号化してから送り、サーバーは暗号文を保存して中継するだけにする。

## 使い方

1. ボード一覧で「🔒 エンドツーエンド暗号化」にチェックを入れてボードを作る。
2. ボードの上の「🔒 暗号化」を押すと、鍵の指紋と**鍵付きリンク**(`…?room=…#k=…`)が出る。
   一緒に使う人をいつもどおり招待(または共有リンクを有効に)したうえで、この鍵付きリンクを渡す。
   オーナーの「共有」パネルのリンクにも鍵が付く。
3. 鍵を持たずに開くと、鍵付きリンクか鍵を貼り付ける画面になる。一度開いた端末は鍵を覚えている。
4. メンバーを外したときなどは、オーナーが「鍵を作り直す」。今の中身を新しい鍵で暗号化し直し、
   つないでいる人は切断される。古い鍵では以後の内容を読めない。新しい鍵付きリンクを配り直す。

鍵を持っていても、ボードを開く権限(招待・共有リンク)がなければ開けない。権限(閲覧のみ・編集可など)は
これまでどおりサーバーが守る(閲覧のみの人が送った暗号文は捨てる)。

## 仕組み

| 項目 | 内容 |
| --- | --- |
| 暗号 | XChaCha20-Poly1305(`chacha20poly1305` クレート、Pure Rust、WASM で動く)。ナンスは 24 バイトの乱数 |
| 鍵 | ボードごとに 32 バイト。ブラウザの `crypto.getRandomValues` で作る。サーバーには送らない |
| 鍵の置き場所 | 鍵付きリンクの `#k=…`(フラグメントはブラウザがサーバーに送らない。開いたらアドレスバーから消す)と、開いた端末の localStorage |
| サーバーに預けるもの | 鍵の指紋 `SHA-256("graboard-e2e-key-id\0" ‖ 鍵)` の先頭 16 バイト。鍵が違うときに「鍵が違います」と言うためで、指紋から鍵は戻せない |
| 関連データ | `graboard-e2e/v1/{ボード ID}/{update か snapshot}`。サーバーが別のボードの暗号文を差し込んだり、種類を入れ替えたりすると復号に失敗する |
| 長さ | 平文を 256 バイト単位に切り上げてから暗号化する(1 文字の編集かどうかを長さから読ませない) |
| 暗号文の形 | 版 `0x01` + ナンス 24 バイト + 暗号文 + 認証タグ 16 バイト |

実装は `crates/board-e2e`(暗号)、`crates/board-server/src/sealed.rs`(保存形式)、
`crates/board-web/src/e2e.rs` と `app/e2e_ui.rs`(ブラウザ側)。

### 同期

サーバーは鍵を持たないので yrs の更新を合成できない。そこで暗号文を通し番号付きのログとして持つ
(`board_core::protocol` の `Sealed` / `SealedSync` / `Compact`)。

- 参加するとサーバーはログ全体(`SealedSync`)を送り、クライアントが復号して 1 つにまとめて取り込む。
- 編集は暗号化して `Sealed` で送り、サーバーは番号を付けてログの後ろに足し、ほかの人に配る。
- ログが 64 件を超えたら、編集できる人がボード全体を 1 つの暗号文にまとめて `Compact` で送り、
  サーバーは先頭からその範囲を置き換える(先にほかの人がまとめていたら何もしない)。
- 保存データ(`rooms` テーブル)は `GBE1` で始まるログで、平文のボードと見分ける。

### 暗号化されないもの

- ボードのタイトル、メンバー・権限・チームなどの設定(ボード一覧や権限の判定にサーバーが使う)
- カーソルの位置と名前、表示範囲、絵文字リアクション、音声通話の接続手順(音声そのものは P2P で、サーバーを通らない)
- 誰がいつ参加したか(下の「悪用への備え」)

### 使えない機能

サーバーが中身を読む・受け取る機能は、暗号化ボードではサーバーが断り(`409`)、画面からも隠す。

AI(要約・グループ分け・議事録・質問・マインドマップ・図の生成・手書きの AI 整形)、コメント、
バージョン履歴、Web に公開、動画メモ、課題カード、サーバーのプラグイン、REST API での読み書き、
ボード一覧の中身の検索(タイトル・タグでは探せる)。画像は中身と一緒に暗号化されるので使える。
REST API・SDK からは暗号化ボードを作れない(鍵はブラウザで作るもののため)。

## 悪用への備え

運営側が中身を確かめられないので、次の 3 つで備える。

- **管理者がオン・オフする**
  - サーバー全体: 環境変数 `E2E_BOARDS`(既定 `1`)。サーバー管理者(`ADMIN_LOGINS`)はボード一覧の
    「通報」パネルからも切り替えられ、そちらが優先する。
  - チームのボード: チームの管理者・オーナーがチームのパネルで「許可する / 禁止する」(既定は**禁止**)。
    暗号化ボードは、許可していないチームには移せない。
  - 止めても、すでにある暗号化ボードは持ち主が開ける(中身を失わせないため)。新しくは作れない。
- **使った記録を操作ログに残す**(中身は残さない・残せない)
  - `board.e2e.create`(作成)、`board.e2e.open`(参加。同じ人・同じボードは 10 分に 1 回)、
    `board.e2e.rotate`(鍵の作り直し)、`board.report`(通報)、`board.suspend` / `board.unsuspend`(利用停止)、
    `report.handle`(通報への対応)、`server.settings` / `team.settings`(オン・オフ)。
- **参加者が通報できる**
  - ボードを開ける人は「🔒 暗号化」パネルの「このボードを通報する」から、理由とコメントを付けて通報できる。
    **自分の判断で**ボードの文字を添えられる(添えなければ、管理者にも中身は見えない)。
  - 通報はサーバー管理者(全体)と、チームのボードならチームの管理者に届く(ボード一覧の「通報」)。
    管理者はボードを**利用停止**にでき、そのボードは誰も開けなくなり、つないでいる人も切断される
    (内容は消えない。解除もできる)。通報はどの種類のボードにもできる。

## API

| メソッド | パス | 内容 |
| --- | --- | --- |
| `POST` | `/api/boards` | `{"title": "…", "e2e": "<鍵の指紋>"}` で暗号化ボードを作る |
| `GET` | `/api/e2e` | 自分が暗号化ボードを作れるか(`enabled`、許可されたチーム `teams`) |
| `PUT` | `/api/e2e` | サーバー全体のオン・オフ `{"enabled": bool}`(サーバー管理者) |
| `PUT` | `/api/teams/{id}/e2e` | チームでの許可 `{"allowed": bool}`(チームの管理者) |
| `POST` | `/api/boards/{id}/e2e/rotate` | 鍵の作り直し `{"key_id": "…", "snapshot": "<新しい鍵で暗号化した全体の base64>"}`(オーナー) |
| `POST` | `/api/boards/{id}/reports` | 通報 `{"reason": "illegal|leak|harassment|spam|other", "comment": "…", "evidence": "…"}` |
| `GET` | `/api/reports[?team=…]` | 通報の一覧(サーバー管理者・チームの管理者) |
| `PUT` | `/api/reports/{rid}[?team=…]` | 対応 `{"status": "resolved|dismissed|open", "suspend": bool}` |
